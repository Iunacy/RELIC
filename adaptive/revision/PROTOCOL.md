# Adaptive-v0 correctness revision

This opt-in MuJoCo research experiment is independent of the NVIDIA/Nebius integration workstream. Production controller gains, Cartesian execution, Ruckig and double-S experiments are unchanged. The original 64-episode evaluation is historical development evidence, not an independent confirmatory test.

The frozen machine-readable protocol is copied to `adaptive/runs/revision-20261022/protocol.json` before collection, tuning or final evaluation. It fixes the split, acceptance gate, model settings, safety rules, bootstrap seed and outcomes. All new outputs are under that separate ignored run directory. Existing evidence and fixtures are protected by `historical_hashes.json`.

The split hash-ranks a 10,000-family candidate pool with a fixed salt. Sixty-four training families, eight development families and forty final evaluation families are disjoint. Each family is executed on both embodiments under all eight conditions. These produce 1,024 teacher episodes and 640 evaluation conditions; their independent units are 64 and 40 base families, respectively, not individual episodes or timesteps. Final partitions each contain ten families: unseen trajectory, parameter combination, severity, and a common-joint transfer probe. Both embodiments occur in each partition. All final families have new seeds and trajectories. Training severity is .25–.67, held-out severity .85–.97; combined-fault combination-test severity is .78. The combination test holds out numerical parameter combinations, not an entirely new fault mechanism.

`restored_nominal` uses exactly nominal physics after a fresh reset. It is a reproducibility control paired with nominal, not a degradation-then-recovery experiment. Primary aggregate metrics exclude this duplicated condition. Historical files retain their original `recovery` label for provenance; no recovery claim is supported by those files.

ILC collects three fixed proposals per training episode. Each proposal is projected onto the frozen per-joint magnitude and correction-rate constraints and replayed in closed loop. Acceptance requires full execution, Success or NonConvergence outcome, no fallback/contact, RMSE below .995 times the previous best, and final Cartesian error no greater than max(previous best + .25 mm, .5 mm). Accepted proposals must produce identical telemetry on a fresh verification replay. Rejected proposals and incomplete processes remain on disk. Eight-iteration convergence probes compare zero lead to a 20-tick (40 ms) advance of previous-episode error. They use training families only and do not choose final evaluation criteria. The original two-family probe is retained; a separately registered 32-family replication uses one cyclically balanced condition per family on both embodiments (64 paired conditions). Its extra iterations do not enter model fitting. Native saturation counters describe analytical requests; ILC saturation rates are computed independently from the bounded replay sequences, rather than interpreting native learned-controller counter zeros as absence of saturation.

Inference features contain analytic current reference derivatives, current pre-step measurements, previous errors, previous applied correction and public geometry/joint descriptors. Complete previous episodes are allowed only in the offline teacher. The endpoint measured after the current step, future measurements and randomized physical parameters are excluded from inference. A replay-valid ILC sequence is an open-loop teacher, not a proven statewise optimal action; its imitation must still pass closed-loop evaluation. Accepted best-sequence targets are paired with baseline and accepted endpoint rollouts to expose both uncorrected and corrected causal histories.

Eight of the 64 collected training families are reserved for validation. Nested training-pool prefixes of 8, 16, 32 and 64 give 7, 14, 28 and 56 fitting families. The fixed eight-family validation corpus is available at every point, so total model-selection exposure is 15, 22, 36 and 64 families, respectively. Reports name fitting, validation and total exposure counts; these are not four independent collection campaigns. Validation families never contribute gradient updates. The same held-out validation families are used for the shared model and experts.

Matched-budget shared and expert-bank models use identical available rows per embodiment and identical actual minibatch exposures. The shared model gets 960 updates, each expert 480, with batch size 2,048. Both expose the same union of training samples. The expert bank has twice the parameter count. Shared training on both embodiments is a familiar-embodiment comparison, not zero-shot transfer. Only the explicitly registered three-to-four-joint common-joint probe tests transfer; the reverse direction is untested. Full-data models are a separate 24-epoch comparison. Validation reports include normalized MSE for learned, zero and copy-previous predictions. Copy-previous starts at zero in closed loop, so its unforced execution equals zero correction; a low offline MSE does not establish useful feedback.

Analytical competitors use nominal-model gravity torque divided by nominal kp=200, plus velocity lead. An integral/past-error variant adds causal error feedback with magnitude/rate-aware anti-windup and a bounded integral state. Development-only search selects among three velocity leads and two integral/error pairs plus gravity-only. No production gains are tuned. All methods use identical command, sampled-path and observed-motion monitoring.

An invalid correction latches withdrawal for the rest of an episode. Each tick moves the applied correction toward zero by at most the configured per-joint rate, then validates the resulting command and connecting sampled path. Withdrawal infeasibility terminates with `WithdrawalInfeasible`; unsafe observed motion uses the common stopping rules. Checks are discrete samples, not a continuous collision guarantee.

Final comparisons pair methods on identical trajectory/physics specifications. Bootstrap samples complete base families with replacement, keeping both embodiments and all conditions together; 4,000 replicates and the fixed seed yield percentile 95% intervals. Incomplete runs remain in outcome/success counts; paired continuous metrics omit incomplete pairs and disclose the omission count. Do not infer superiority from mean error alone, overlapping intervals, or training loss. The common-joint transfer probe predicts only joints 0–2 of the four-joint arm from a three-joint expert and leaves the wrist conventional. Its common-joint RMSE and full-arm task success are distinct outcomes.

# Research execution boundary

`adaptive/episode.cpp` independently samples joint-space endpoints, generates analytic quintic references, performs its own admission checks and runs a fixed 500-tick settlement window. It uses the existing Simulation, health, contact and configuration interfaces. It does not call production `execute_cartesian_motion`, does not exercise the IK/planner selection path and does not reproduce production settlement dwell semantics. A successful research episode is not evidence that the learned controller has been integrated into production Cartesian execution.

`adaptive/recorder.hpp` is an independent long-form research recorder, not an extension of production `TraceWriter`. Production TraceWriter writes wide snapshot rows with tool pose and per-joint observations/commands/torques. The research recorder adds pre-step observations, analytic reference derivatives, endpoint and interval-start effort, corrections, phase and safety provenance; it emits one row per joint per tick and a separate JSON metadata document. The original requirement to adapt the existing recorder was not fulfilled by adaptive-v0. This revision documents that limitation explicitly rather than implying production recorder integration. CSV/gzip conversion and validation remain available, but the two layouts are not interchangeable without a deliberate adapter.

# Reproduction

Use MuJoCo 3.16.0 and a CPU PyTorch environment; no external datasets, pretrained models or cloud services are required. Run `bash adaptive/revise.sh`. The script builds the opt-in executable, runs tests, freezes the protocol, qualifies withdrawal and teacher collection, collects teachers, runs development tuning and convergence probes, prepares data, trains and evaluates. Run `python adaptive/revision_demo.py` for a four-controller motion/feedback demonstration on the predeclared first severity-test family, four-joint combined-fault condition. Outputs are resumable. Fully validated completed runs are reused after identity checks; interrupted directories are retained with an `interrupted` suffix and retried. Reproducibility depends on the pinned executable, bounds and saved configurations. Keep the generated run directory outside Git.
